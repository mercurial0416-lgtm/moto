# 기존 데이터 유지 업데이트 / 서명키 검증

Android가 앱 업데이트로 인정하려면 패키지 이름과 APK 서명 인증서가 같아야 하며, 새 versionCode가 이전 버전보다 높아야 합니다. APK 자체의 SHA256은 배포 파일 무결성을 확인할 뿐, 업데이트 호환성을 보장하지 않습니다.

- 설정 > 앱 정보 > **설치 서명 SHA-256** 버튼을 눌러 현재 설치된 인증서의 공개 지문을 복사할 수 있습니다.
- GitHub Actions가 매번 생성하는 기본 debug 키는 러너마다 다를 수 있으므로 설치된 DB(511)/DC(512)와 덮어쓰기 호환이라고 보장할 수 없습니다.
- 기존 설치본을 지우거나 앱 데이터를 초기화하지 마세요. 키가 다르면 Android가 설치를 거절하는 것이 정상입니다.
- 장기 업데이트용 release APK는 **기존 앱을 서명한 정확한 비공개 키**가 있어야 합니다. 앱에 포함된 공개 인증서로 비공개 키를 역산할 수는 없습니다.
- 기존키가 준비되어 있는 경우에만 GitHub Actions `moto-hub-signed.yml`의 환경변수/Repository Secrets에 키스토어(base64), 별칭, 비밀번호, 예상 공개 인증서 SHA-256을 저장해 빌드할 수 있습니다. 비공개 키를 Git 커밋, APK 또는 채팅에 올리지 마세요.
- 서명이 같다고 해도 `백업 · 복원 > 모든 기록 ZIP으로 내보내기`를 실행해 **휴대폰 밖**에 사본을 만들어 두세요.
- 현재 설치된 인증서 지문을 알더라도, 대응하는 기존 서명 비공개 키가 없으면 무삭제 교체 APK는 만들 수 없습니다.
