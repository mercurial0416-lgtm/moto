# MOTO HUB · 빠른 개선 프로세스 및 확인된 후속 과제 (UX24)

## 개발 속도 원칙 (사용자 요청)
1. 최신 소스는 `build/di518-ux4-prebuild-20261020/MOTO-HUB/`. 루트 ZIP에서 앱을 재생성하지 말 것.
2. 이슈와 영향을 확인하고 **한 차례 작업의 수정 범위 2~4개 수준**을 사전에 확정. 새 기능을 계속 덧붙여 종료를 늦추지 않음.
3. 관련 파일만 읽고 한 번에 수정+테스트 추가. 소스가 이미 구현한 GPS, GPX, 정비, 사진, 위젯 등은 재작성 금지.
4. 1개 작업 브랜치, 가능한 1개 기능 커밋, CI `Java 회귀 → :app:assembleDebug/:app:lintDebug/:app:testDebugUnitTest` **한 번** 실행. 실패/수정 후에만 재실행.
5. 통과하면 바로 PR 병합 및 체크포인트 업데이트. 끝없는 '더 찾아서 개선' 반복 작업을 이번 회차 종료의 필수 조건으로 삼지 않는다.
6. 설치 앱 삭제 금지. CI debug APK는 사용자 설치본과 서명이 맞는 배포본이라는 뜻이 아니다. 고정 서명 Release는 기존 설치 인증서와 동일 여부를 확인한 뒤에만 사용.
7. 개인키 및 GPS 등 개인 데이터 절대 커밋하지 말 것.

## UX25 이후 후보 (이번 턴에는 추가 구현하지 않음)
1. **복원 도중 강제 종료 시 복구**: 현 `RestoreArchive.Prepared.install`은 예외 발생 시 롤백하지만 앱 프로세스 종료를 가로채지 못함. 기존 `moto-rollback-*` 폴더를 보존하는 정책은 있으나 재시작 시 자동 복구 가능한 검증된 영속 저널은 없음. 데이터 유실 방지 설계·테스트를 별도 묶음으로 처리.
2. **온라인 모델 이미지 출처 메타데이터 구조 검증**: `BackupFormat.selectedModelMetadata`는 정규표현식으로 `userSelected`를 판단. JSON의 실제 최상위 boolean인지 검사하는 구조적 검증을 도입하고 가짜/중복 키/악성 입력을 재현할 것.
3. **대량 기록/UI 반응 속도**: 페이징·라이딩 기록 비동기 처리는 있지만 10,000건 DB 및 여러 카테고리에서 화면 지연 측정과 최적화를 위한 실측/회귀가 필요.
4. **사진 로딩 폴백**: Wikimedia 서버 실패나 특정 브랜드/연식 검색 실패 시 사용자 사진 등록이 대체 경로로 존재함. 실기기 실패 HTTP/디코딩 원인을 확인하고 불필요한 연속 네트워크 대기 감소를 검토.
5. **실기기 + 배포**: Android 16에서 GPS 백그라운드/알림/사진/업데이트 설치, 기존 APK와 고정 서명 SHA-256 일치 여부를 검증해야 함. 비공개 키를 공개 저장소에 두지 말 것.

이 목록은 미해결 가능성이 있는 개선 후보이며, 사용자 단말에서 오류가 실제 발생했다고 확인된 목록은 아니다.
