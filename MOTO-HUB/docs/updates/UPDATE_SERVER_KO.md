# APK 직접 배포 업데이트 — 서버 미연동

앱: 설정 → 앱 업데이트. 배포 서버가 없는 기본 빌드는 미연동으로 표시하고 네트워크 요청을 보내지 않습니다.
배포 운영자가 신뢰하는 HTTPS 메타데이터 URL을 빌드 시 지정합니다:
```
./gradlew :app:assembleDebug -PupdateManifestUrl=https://YOUR-DOMAIN/moto/latest.json
```
운영 배포는 별도 사용자 소유 릴리스 서명키로 빌드하세요. 현재 ZIP에는 서명키가 없습니다. 이전 설치본과 인증서가 다르면 앱이 업데이트 설치를 거부합니다.

JSON 형식(아래 값은 예시이며 실제 서버/해시가 아님):
```json
{
  "packageName": "com.motohub.next",
  "versionCode": 406,
  "versionName": "4.0.0-alpha6",
  "minSdk": 26,
  "apkUrl": "https://YOUR-DOMAIN/moto/MOTO-HUB.apk",
  "sizeBytes": 123456,
  "sha256": "실제 APK의 64자리 SHA-256으로 교체",
  "notes": "변경 사항"
}
```

요구: HTTPS200 직접 응답(리다이렉트 불허), 메타데이터 최대64KiB, APK 최대200MB, 정확한 바이트크기/해시. APK 먼저 업로드하고 최신 메타데이터는 마지막에 교체. 롤백 버전을 새 업데이트로 설치하려면 높은 versionCode로 재빌드.
흐름: 수동 확인 → 버전/변경사항 알림 → 사용자 다운로드 선택 → 백그라운드 다운로드 → 크기/SHA/패키지/상위버전/동일서명 검사 → 사용자 설치 선택 → 필요시 Android 설치허용 설정 → 다시 설치 선택 → 시스템 설치 확인.
설치 직전에 파일 SHA를 다시 검사합니다. 라이딩 중 설치는 거부합니다. 앱 데이터 삭제/앱 제거는 호출하지 않습니다. 데이터 보존은 실제 업데이트 설치 테스트로 추가 확인해야 합니다.
캐시가 OS에 의해 지워지면 다시 다운로드합니다. 이전 완료 파일은 캐시에 남을 수 있으며 재시도 시 부분 파일은 폐기됩니다. 자동 갱신/정기 확인/다운로드 재개/강제 설치는 구현하지 않았습니다.

검증: 메타데이터·HTTP 금지·크기제한·SHA·읽기전용 APK provider·미연동 UI의 자동 테스트 포함. 실제 업데이트 서버와 설치 확인 화면을 통한 설치/취소/실패/데이터 보존은 아직 실행하지 않았습니다. 배포 서버와 테스트용 다음 버전 APK가 필요합니다.
원래 앱의 업데이트 서명 전략과 실제 배포 채널을 확정하기 전 상용 업데이트 완료로 표시하지 마세요.
