# UX42 · 이어받기, 설치 전 복구 지점, 큰 글씨 대응

## 실제 변경
- HTTPS 요청에 `Range: bytes=N-`를 사용해 같은 공개 업데이트 APK의 중단된 파일을 재사용.
- 진행 중 파편은 manifest SHA-256으로 명명된 `<sha256>.part.apk`에만 저장. 재시작 시 기존 부분을 해시 계산한 뒤 이어받음.
- 서버 HTTP 206 `Content-Range`의 시작 오프셋·끝·총길이를 독립 정책으로 검증. 200 응답이면 기존 파편을 덧붙이지 않고 초기화해서 처음부터 저장. 416 응답은 새 다운로드로 재시도. 전체 SHA-256/크기/서명 검증은 기존과 동일.
- 7일 이상 된 **다른 버전**의 중단 파편만 정리하고 현재 파편·기기 데이터·GPS·복원 지점은 보호.
- 시스템 설치 화면을 열기 전 `motohub-v3.json` 원본을 앱 내부 JSON 복구 지점으로 **원자적 저장 후 다시 읽어 바이트 일치/Store 파싱 검증**. 실패하면 설치 진행 금지.
- 이 복구 지점은 주유·정비 등 DB 기록만 포함. 사진·GPS는 별도 **암호화 전체 백업** 동선을 설치 전 안내.
- 새 앱 버전으로 실행될 때 저장 데이터가 로드됐는지 확인하고, 설치 전 복구 지점 확인 결과를 안내. 사용자의 기록을 자동으로 덮어쓰지 않음.
- 고배율 글씨에서 홈 바이크명/정비 상태/거리/연비를 세로로 배치하고, 차고 목록 금액과 매물명/상태도 충돌 없이 배치하도록 수정.

## 검증 경계
- `tests/UpdateResumePolicyTest.java` 18개 검증 시나리오, `tests/run-ux42-update-integrity-tests.sh` 정적 소스 연결 검사 추가.
- 실제 Android 빌드·Gradle lint·휴대폰에서 네트워크 끊김/이어받기/새 APK 덮어쓰기 검증은 아직 필요.
- 저장소에 공개된 인증서 지문은 고정값, 비공개 서명키는 수정하지 않음. 새 APK 자체의 서명이 확인되기 전까지 배포 금지.
- 기존 설치 앱과 데이터는 지우지 말 것.
