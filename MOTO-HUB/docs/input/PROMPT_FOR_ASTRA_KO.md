# MOTO HUB 완성형 Android 앱 개발 — Astra/Codex 단일 작업 지시문

너는 시니어 Android 엔지니어, 모바일 프로덕트 디자이너, 백엔드/보안 담당자다. 첨부 ZIP의 기존 동작과 데이터 구조를 읽고 실제 설치·검증 가능한 개인용 안드로이드 바이크 앱으로 개선해라. 설명이나 디자인 시안만 출력하지 말고 **코드 변경 및 검증된 결과물**을 남겨라.

## 0. 핵심 전제 — 중요
- 현재 앱은 `legacy/current_app/index.html`을 최소 WebView APK에 담은 구조이고 정식 Android Studio/Gradle 프로젝트가 아니다. ZIP의 `legacy/legacy_apk_assembler_reference.py`는 **참고 코드 일부**일 뿐 빌드 가능한 프로젝트가 아니다. 기본 패키지 ID는 `com.motohub.app`, 기존 WebView localStorage 키는 `motohub_personal_v1`이다.
- 첨부의 APK는 **기존 앱 참고용**이다. 실제 단말 검증은 이전 작업에서 되지 않았다. 동작을 가정하지 말고 진단하라.
- **서명키는 첨부하지 않았다.** 기존 APK와 동일한 서명키 없이는 정상적인 덮어쓰기 업데이트를 보장할 수 없다. 새 설치판과 덮어쓰기판을 구분하고, 서명키를 요청해야 하는 시점과 로컬에서 안전하게 사용하는 방법을 문서화하라. 코드·저장소·채팅에 키를 넣지 마라.
- 내 용도는 **개인용 + 친구와 그룹 라이딩**이다. 한국어 전용 우선, 기본 앱은 오프라인에서 작동. 라이딩 중 휴대폰 조작은 유도하지 마라.
- 정보가 없는 항목은 더미/샘플임을 명시하고 API 미연동을 실제 연결처럼 꾸미지 마라.
- Android 타깃은 현대 기기 기준으로 운영체제 요구 정책에 맞춰 구성. 기존 SDK 28 타깃을 그대로 답습하지 마라.

## 1. UI/UX 전면 재설계 — 최우선
이 부분은 단순 색상/여백 변경이 아니다. 사용자가 이전 UI를 여러 번 불편하다고 했으므로 정보 구조와 탐색부터 다시 설계한다.
- 실제 네이티브 안드로이드 앱처럼 보여야 한다. 가능하면 Kotlin + Jetpack Compose + Material 3을 사용하되, 원본 HTML 기능을 보존하면서 점진 이관하는 방법도 허용. 단, 무조건 WebView만 그대로 감싸는 결과는 불합격.
- **AI스럽지 않게**: 거대한 홍보 히어로, 형광 그라데이션, 의미 없는 카드 격자, 과장된 그래프, 텍스트 과밀, 동일한 둥근 카드 무한반복 금지.
- 타이포 위계 분명히, 16sp 내외 본문, 터치 목표 48dp 이상, 충분한 대비, 버튼과 리스트 높이, 안드로이드 뒤로 가기/키보드/상태표시줄/제스처 내비게이션 안전영역 처리.
- 삼성 갤럭시 S25급 폭을 주 기준으로 320/360/393/412dp 및 글자 확대(최소 1.3배) 상황에서 가로 넘침, 잘림, 키보드 가림, 하단바 중복이 없어야 한다. 다크/라이트 기본 제공.
- 홈: 대표 바이크·주행거리·최근 활동·다가오는 정비/보험·관심 매물 1~2개를 **첫 화면에서 읽히게**. 주유/정비 추가는 1~2번 터치로 도달.
- 하단 탐색: 홈 / 매물 / 라이딩 / 차고·정비 / 더보기 정도로 정리. 긴 설정은 별도 하위 화면.
- 매물: 중고거래 앱 같은 텍스트·가격·연식·km 위계의 목록. 정렬, 필터, 등록, 수정, 비교, 가격 변화, 매물 열기. 상태 확인되지 않았으면 '확인 필요'.
- 정비: 차량별 타임라인과 다음 점검, 기록 추가 흐름 간결하게. 폼의 필수 항목 최소화, 적절한 숫자 키보드.
- 친구/그룹: 지도 중심 화면, 명확한 위치 공유 상태, 마지막 갱신 시간, 큰 '공유 중지' 버튼. GPS 정확도 불량과 오프라인 표시.
- 로딩/빈 화면/권한 거절/데이터 없는 상태/오류/인터넷 끊김 등을 일관성 있는 실용적 UI로 디자인.
- 실제 기기에서 앱 스크린샷 또는 에뮬레이터 스크린샷을 만들어 UI 점검하고 문제를 수정. 스크린샷 생성이 안 되면 사유 표기.

## 2. 오프라인 필수 기능 유지·개선
- 다중 바이크 등록/수정/삭제, 대표 차량 설정, 차량별 주행거리 및 소유 이력
- 정비 항목·교환 주기(차량별 사용자 편집 가능)·날짜/km 알림, 보험 갱신 예정
- 주유비·연비·정비비·보험·부품·기타 유지비 관리와 월별 집계
- 중고매물 URL 수동 저장, 가격/연식/km/튜닝/퀵시프터/상태 기록, 중복 체크, 비교/가격변동, 구매 전 체크리스트
- 바이크별 차종 비교, 기변 실질 비용 계산, 보호장구 관리, 출발 전 안전 점검
- 라이딩 코스 저장, 지도 앱 연결, 거리 기록, GPX 가져오기/내보내기(가능한 기능의 범위를 명확히 표기)
- 데이터 JSON 내보내기·불러오기 및 기기 변경 대비 백업. 기존 WebView 데이터의 **실제 마이그레이션 경로** 또는 사용자 백업 수동 가져오기를 제공. 사용자 동의 없는 초기화 금지.
- 내 데이터는 로그인을 요구하지 않는 오프라인 공간에 저장. 친구 기능만 로그인 필요.

## 3. 친구 및 실시간 GPS — 작동하는 수직 기능 구현
- 친구 계정 로그인(지원 가능한 안전한 인증 방식), 친구 코드/초대 URL, 요청 수락/거절, 차단.
- 그룹 라이딩 방 생성/참여/종료, 초대·집결지·중간 경유지 공유.
- **명시적으로 공유를 시작한 방 참여자끼리만** 좌표를 확인. 친구라는 이유만으로 위치 자동 공개 금지.
- 지도에 위치 마커/별명/방향/최종 갱신 시각, 잠깐 정차·주유·휴식 상태, 네트워크 끊김과 오래된 좌표 표시.
- 안드로이드 Foreground Service와 **위치 공유 진행 중 지속 알림**을 구현. 화면이 꺼진 상태의 공유는 OS/권한/배터리 예외에 따라 제한이 있음을 처리. 권한 거절 시 대체 UX 제공.
- 갱신 주기는 활동/속도/배터리에 따라 동적으로 조절(예: 주행 시 5~10초 목표, 정차 시 더 느림); 서버 과금과 정확도 고려. 백그라운드 GPS 사용은 실제 단말에서 검증 전 '검증 완료'라고 하지 마라.
- 공유는 기본 꺼짐, 모든 위치 공유에 명시적인 ON/OFF, 공유 대상/세션 명시, 종료 시 중지. 오래된 좌표 자동 만료/삭제, 기본적으로 라이브 좌표 장기 보관 금지. 라이딩 역사적 기록은 별도 동의.
- 긴급 SOS 표시가 필요하면 확인/취소와 오작동 방지 설계. 앱은 구조·응급서비스를 대신하지 않는다.
- 백엔드는 Supabase Auth, Realtime Broadcast, RLS 등을 우선 검토하되 작업 환경과 실제 권한에 맞게 선택. DB 스키마·마이그레이션·보안 정책·권한 테스트 제공. 승인되지 않은 사용자는 타인의 위치를 읽거나 임의로 게시할 수 없도록. 비밀키는 클라이언트에 넣지 않는다.
- 외부 계정·프로젝트/API 키가 없어서 실서비스 연결이 불가능하면 코드/설정 예제를 완성하되 상태를 **'백엔드 연결 대기'**로 표시. 테스트 모드로 허위 위치를 실제 친구처럼 보여주지 마라.

## 4. 업데이트·안정성
- 앱 내 버전 확인: HTTPS 업데이트 manifest를 통해 버전·변경점·공식 다운로드 주소 제공. APK 다운로드 및 Android 설치 승인은 사용자가 직접 수행. 서명 불일치일 경우 덮어쓰기 불가 안내.
- UI 리소스만 원격 갱신 가능하게 하려면 무결성/보안/오프라인 캐시 보장. 개인정보를 외부 서버로 몰래 전송하지 마라.
- 사용자 데이터 백업/복원 실패 처리, 앱 강제종료 후 복구, 권한/네트워크 예외 처리, 임의의 스크레이핑이나 로그인 우회 금지.

## 5. 토큰/작업량 최적화와 완료 조건
- 전체 요구를 **단일 작업 지시**로 받되 내부적으로 차례대로 실행해라. 무한 리서치나 불필요한 재구현 금지.
- P0: 기존 앱 분석, 실행 가능 Android 프로젝트 구성, **UI 전면 변경**, 오프라인 주요 CRUD 안정화/데이터 백업, 빌드 가능한 APK.
- P1: 친구/그룹/실시간 위치 공유 핵심 한 흐름 구현(두 테스트 계정의 공개 승인 시연이 목표), 필수 Android 위치 권한 및 foreground service.
- P2: 고급 GPS 추적/지도 코스/앱 업데이트/세부 부가 기능. P0/P1이 안 되면 P2로 넘어가지 마라.
- 사용량이 부족해지면 멈추지 말고 P0 완성과 테스트를 우선하고, 남은 일을 구체적인 TODO로 남겨서 다음 세션에서 이어갈 수 있도록 하라. 한도·시간을 근거 없이 약속하지 마라.
- **완료 체크**: 프로젝트 열기 → 빌드 명령 → APK 산출물 확인 → 앱 시작/화면 이동/저장/복원 스모크테스트 → 작은 화면 테스트 → 친구 공유 접근제어 테스트(가능하면). 불가한 항목은 '미검증'으로 표시.
- 최종 산출물은 APK(가능한 경우), Android Studio에서 열리는 전체 소스, README, 이전 앱 데이터 이동/서명키 안내, 변경사항, 테스트 통과 목록/미검증 목록. 도구 접근이나 계정 제한은 구체적으로 밝히되 완성하지 않은 기능을 완성했다고 주장하지 마라.

**시작:** 첨부된 README와 HTML 소스의 데이터 구조를 먼저 검사하고 P0부터 실제 수정에 착수해라. 진행 중 UI 수정은 기존 색상만 바꾸는 식으로 처리하지 마라.
